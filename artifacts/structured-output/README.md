# Описание проекта

Цифровой сотрудник представляет собой систему автоматизированной оценки качества RAG (Retrieval-Augmented Generation), предназначенную для анализа эффективности поиска релевантной информации, оценки качества сгенерированных ответов, выявления ошибок и формирования рекомендаций по совершенствованию RAG-пайплайна.

## Текущая реализация

В ветке `task/01-structured-output` реализован учебный прототип для задания "Получение ответа от LLM в определенном формате".
Приложение:
- принимает вопрос, ответ RAG-системы, эталонные и найденные чанки;
- обращается к локальной LLM через OpenAI-совместимый API;
- передает заданную температуру генерации;
- использует структурированный вывод с JSON Schema;
- проверяет результат через Pydantic;
- возвращает бинарную оценку, теги ошибок и краткое обоснование;
- обрабатывает некорректные запросы и ожидаемые ошибки обращения к LLM.

Подготовка входных данных, расчет метрик Retrieval, обработка файлов и формирование Excel-отчетов в этот прототип не входят.

Ветка `main` предназначена для целевого проекта. Приведенные ниже инструкции относятся к ветке задания.

## Установка

Команды ниже предназначены для PowerShell. Выполняйте их из корня клонированного репозитория.

### 1. Переключиться на ветку задания

При чистой рабочей папке:

```powershell
git fetch origin
git switch task/01-structured-output
```

### 2. Создать окружение и установить зависимости

Требуется установленный Python 3.15.

```powershell
py -3.15 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

Команды обращаются непосредственно к интерпретатору виртуального окружения, поэтому активировать его отдельно не требуется.

### 3. Подготовить Ollama

Установите и запустите [Ollama](https://ollama.com/download), затем скачайте модель:

```powershell
ollama pull qwen2.5:3b
ollama list
```

Проверить обычный ответ модели:

```powershell
ollama run qwen2.5:3b
```

Для выхода из диалога используйте `/bye`.

### 4. Подготовить конфигурацию

Если локальный `.env` еще не создан:

```powershell
Copy-Item .env.example .env
```

Пример содержимого:

```dotenv
LLM_BASE_URL=http://localhost:11434/v1
LLM_MODEL=qwen2.5:3b
LLM_API_KEY=ollama
LLM_TEMPERATURE=0
LLM_TIMEOUT_SECONDS=120
```

| настройка | назначение |
|---|---|
| `LLM_BASE_URL` | Базовый адрес OpenAI-совместимого API |
| `LLM_MODEL` | Название модели |
| `LLM_API_KEY` | Ключ или заглушка для локальной Ollama |
| `LLM_TEMPERATURE` | Температура при отсутствии поля в HTTP-запросе |
| `LLM_TIMEOUT_SECONDS` | Тайм-аут клиента LLM в секундах |

Для локальной Ollama значение `ollama` используется как заглушка и не является секретом.

Переменные окружения имеют приоритет над `.env`. После изменения настроек работающий процесс приложения следует перезапустить.

Приложение запускается на локальном интерфейсе `127.0.0.1`. Публичное развертывание и аутентификация в текущий прототип не входят.

## Контракт API

### `POST /evaluate`

Оценивает один ответ RAG-системы.

### Запрос

| поле | тип | правила |
|---|---|---|
| `question` | `string` | Обязательный непустой вопрос; пробелы по краям удаляются |
| `answer` | `string` | Обязательное поле; пустой ответ допускается |
| `reference_context` | `array[string]` | Обязательный список эталонных чанков; может быть пустым |
| `context` | `array[string]` | Обязательный список найденных чанков; может быть пустым |
| `temperature` | `number` | Необязательное конечное число от 0 до 2 |

Если `temperature` передана явно, используется значение запроса. В противном случае используется `LLM_TEMPERATURE`.

Неизвестные поля запрещены. Эталонный ответ и идентификаторы чанков в текущем контракте не используются.

Пример запроса на синтетических данных:

```json
{
  "question": "Во сколько открывается тестовый сервис?",
  "answer": "Тестовый сервис открывается в 09:00",
  "reference_context": [
    "Тестовый сервис работает ежедневно с 09:00 до 18:00"
  ],
  "context": [
    "Тестовый сервис работает ежедневно с 09:00 до 18:00"
  ],
  "temperature": 0
}
```

### Успешный ответ

HTTP `200`. Пример формы ответа:

```json
{
  "score": 1,
  "tags": [],
  "explanation": "Ответ соответствует вопросу и подтверждается контекстом."
}
```

| поле | тип | правила |
|---|---|---|
| `score` | `integer` | Только `0` или `1` |
| `tags` | `array[string]` | Допустимые теги без повторов |
| `explanation` | `string` | Непустое обоснование оценки |

При `score = 1` список тегов должен быть пустым. При `score = 0` требуется хотя бы один тег.

### Теги ошибок

| тег | значение |
|---|---|
| `wrong_chunks` | Нужные сведения есть в найденном контексте, но ответ опирается на неподходящие фрагменты |
| `not_full` | Пропущены существенные сведения |
| `hallucination` | Добавлены факты, не подтвержденные найденным контекстом |
| `fact_distortion` | Искажен факт из переданных материалов |
| `verbose` | Присутствует существенная лишняя информация |

Тег `retrieval_error` в этом прототипе не выставляется: он относится к отдельной оценке Retrieval.

### Ошибки

| HTTP-код | код в JSON | причина |
|---|---|---|
| `422` | `invalid_request` | Некорректные входные данные |
| `502` | `invalid_llm_response` | Ответ LLM не прошел проверки, пуст, оборван или содержит отказ от оценки |
| `502` | `llm_api_error` | Сервер LLM вернул ошибку |
| `503` | `llm_unavailable` | Не удалось подключиться к LLM |
| `504` | `llm_timeout` | Превышено время ожидания |

Пример ошибки:

```json
{
  "detail": {
    "code": "invalid_request",
    "message": "Проверьте поля запроса.",
    "fields": [
      {
        "field": "body.temperature",
        "type": "less_than_equal"
      }
    ]
  }
}
```

## Структурированный вывод

Приложение формирует JSON Schema из `EvaluationResult` и передает ее в `response_format` запроса к LLM с типом `json_schema`. После генерации приложение проверяет завершение ответа и выполняет валидацию через Pydantic, включая уникальность тегов и связь `score` с `tags`. Промпт задает критерии оценки, а механизм структурированного вывода ограничивает форму ответа. Валидная структура сама по себе не подтверждает правильность оценки. Для генерации установлен лимит 512 выходных токенов. Автоматические повторные запросы SDK отключены.


Команда выводит модель, температуру, время выполнения и проверенный результат.

```powershell
.\.venv\Scripts\python.exe -m pytest -v
```

Подтвержденный результат в проверенном окружении - 27 пройденных тестов:

- 21 проверка схем и правил валидации;

В HTTP-тестах обращение к LLM заменяется имитацией. Они проверяют обработку запросов и ошибок, но не измеряют качество реальной модели.

## Эксперимент с температурой

Запуск:

```powershell
.\.venv\Scripts\python.exe -m app.experiment
```

Используются три синтетических примера:

1. полностью корректный ответ;
2. ответ с искаженным временем открытия;
3. неполный ответ без времени закрытия;

Для каждого примера выполняются два запроса при температурах `0.0`, `0.5` и `1.0`. Всего - 18 попыток.

Результаты сохраняются после каждой попытки в `artifacts/structured-output/`.

### Полученные результаты

Исходный файл: `experiment_20261127T000011397627Z.json`.

| температура | прошли валидацию |  совпадение бинарной оценки с ожидаемой | среднее время успешных ответов |
|---|---:|---:|---:|
| `0.0` | 6/6 | 4/6 | 5,85 с |
| `0.5` | 6/6 | 3/6 | 4,88 с |
| `1.0` | 6/6 | 4/6 | 4,49 с |
| Всего | 18/18 | 11/18 - 61,1% | 5,07 с |

Все результаты прошли схему и реализованные проверки приложения. При этом обнаружены содержательные ошибки:

- неполный ответ был признан корректным во всех шести попытках;
- искажение времени обычно обнаруживалось, но классифицировалось как `not_full`;
- отдельные обоснования приписывали ответу сведения, присутствующие только в контексте.

Ожидаемые оценки заданы автором для синтетических примеров, то есть это не независимая экспертная разметка.

## Ограничения

- Качество оценщика требует дальнейшей работы: соответствие JSON Schema не гарантирует правильность `score`, тегов и обоснования.
- Эксперимент содержит три уникальных примера с повторами и не позволяет оценить общее качество системы.
- По полученным временам нельзя установить причинное влияние температуры: порядок запросов фиксирован, загрузка модели отдельно не измерялась.
- Для показанного запуска `ollama ps` сообщал контекст 4096 токенов. Обработка длинных входов и контроль переполнения контекста отдельно не реализованы.
- Поддержка других моделей и OpenAI-совместимых серверов требует проверки их возможностей.
- Прототип не выполняет полноценную оценку Retrieval и не формирует итоговую диагностику всей RAG-системы.
